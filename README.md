# น้องมะระ-สหายเกษตร (MaRa-AgriAlly)

ต้นแบบสำหรับการประกวด: AI Agent รวมผลผลิตเกษตรกรรายย่อยเป็นกลุ่ม แล้วเจรจาขายแทนกลุ่ม
โดยเกษตรกรเป็นผู้อนุมัติดีลเองทุกครั้ง และผู้ซื้อโอนเงินตรงเข้าบัญชีเกษตรกรแต่ละคน

> ข้อมูลทั้งหมดในต้นแบบเป็นข้อมูลจำลอง ไม่ใช่ข้อมูลเกษตรกรหรือราคาตลาดจริง

## สถานะ
- [x] ขั้นที่ 1 โครง repo, ข้อมูลจำลอง (ข้าวหอมมะลิเป็นหลัก + มะระจีน, มันสำปะหลัง)
- [x] ขั้นที่ 2 Deterministic engine + unit test
- [x] ขั้นที่ 3 Mock Buyer API (ผู้ซื้อจำลอง 4 ราย: กดราคา, กลางๆ, ซ่อนค่าหักความชื้น, ค้าส่งผัก) — v2 ตอบสนองต่อหลักฐาน มีข้อโต้แย้ง
- [x] ขั้นที่ 3.5 ราคาตลาดจริงจาก NABC + RAG (custom chunking, BM25 + bigram, รองรับ embedding ภายหลัง)
- [x] ขั้นที่ 4 Agent loop (Nova บน Bedrock หรือ LLM จำลอง + tool calling + guardrails)

- [x] ขั้นที่ 6 (เวอร์ชันเดโม) หน้าเล่นซ้ำการเจรจา `web/index.html` — สร้างจากผลรันจริงด้วย `npm run demo:export`
- [x] ขั้นที่ 7 (พร้อม deploy) SAM template: API Gateway + Lambda × 2 + DynamoDB — ดูหัวข้อ Deploy
- [x] ขั้นที่ 8 LINE OA adapter (โค้ดพร้อม + เทสด้วย LINE client จำลอง 25 ข้อ — **ยังไม่ได้ทดสอบกับ LINE จริง** ดูหัวข้อ LINE)

## RAG (`backend/src/rag`)
- **Custom chunking:** ตัดตามหัวข้อ `##` (1 หัวข้อ = 1 ความคิด) ติด meta `docType/crop/buyer` จาก front matter และ `<!-- buyer: B-C -->` ส่วนที่ยาวเกินแบ่งย่อยแบบมีส่วนซ้อน
- **ค้นหา:** BM25 บน character bigram (ภาษาไทยไม่เว้นวรรค จึงไม่ต้องใช้พจนานุกรมตัดคำ) ไม่ต้องใช้ AWS ผลเหมือนเดิมทุกครั้ง
- **Hybrid:** ถ้ามี embedding model ใน region จะรวมคะแนนความหมาย ถ้าล่มหรือช้าเกิน timeout กลับไปใช้ lexical อัตโนมัติ
- เพิ่มความรู้: เพิ่มไฟล์ `.md` ใน `backend/knowledge/` ไม่ต้องแก้โค้ด

## Agent (`backend/src/agent`)
วงจร: **วางแผน → เรียก tool → ดูคำตอบผู้ซื้อ → ประเมินใหม่ → ทำซ้ำ** จนได้ดีลรออนุมัติ หรือส่งเรื่องให้กลุ่ม

| Tool | ทำอะไร |
|---|---|
| `get_market_price` | ราคาจริงจาก NABC |
| `search_knowledge` | RAG: ประวัติผู้ซื้อ กติกาหักความชื้น แนวทางเจรจา |
| `list_buyers` / `request_quote` | หาผู้ซื้อ ขอใบเสนอราคา |
| `evaluate_offer` | ราคาสุทธิหลังค่าขนส่ง+ส่วนหัก และตรวจ floor ทุกคน (โค้ดคำนวณ ไม่ใช่ LLM) + บอกหลักฐานข้อเสนอของรายอื่นที่อ้างได้จริง |
| `get_negotiation_history` | ผลการเจรจาที่ระบบเคยบันทึกกับผู้ซื้อรายนี้ (หลักฐาน E-HIST) ไม่มีประวัติ = ห้ามอ้าง |
| `submit_counter` | ยื่นข้อเสนอ 1 รอบ: **กลยุทธ์** (8 แบบ) + **เหตุผลสั้น** + **หลักฐานที่อ้าง** + ราคา + ข้อความ / ขอลดส่วนหัก |
| `prepare_deal_for_approval` | เตรียมดีลให้เกษตรกรอนุมัติ (ไม่มี tool ปิดดีล) |
| `escalate_to_farmers` | ส่งเรื่องให้กลุ่มเมื่อไม่มีข้อเสนอผ่าน floor |

**Guardrails (บังคับในโค้ด):** ราคาต่ำกว่า floor · ข้อความมีตัวเลขที่ตรงกับขั้นต่ำ (รวมเลขไทย และตัวเลขจากแหล่งอื่นที่บังเอิญตรง) · **ตัวเลขที่ไม่มีในทะเบียนหลักฐาน** (กันแต่งราคาคนกลาง/สถิติ) · อ้างข้อเสนอของรายอื่นที่ไม่ได้ดีกว่าจริง · เสนอต่ำกว่าที่ผู้ซื้อให้อยู่แล้ว · เกินจำนวนรอบ · เตรียมดีลที่ไม่ผ่าน floor · ส่งเรื่องให้เกษตรกรก่อนต่อรองสักครั้ง → บล็อกและบันทึก `guardrail_blocked`

### เจรจาด้วยหลักฐาน (`agent/evidence.ts`)
- **ทะเบียนหลักฐาน:** ทุกข้อเท็จจริงที่อ้างได้มีรหัส — `E-VOL` ปริมาณ, `E-GRADE` เกรด (ตามที่เกษตรกรแจ้ง), `E-DELIVERY`, `E-LOGISTICS` รถรวม, `E-MKT-*` ราคา NABC, `E-OFFER-*` ข้อเสนอผู้ซื้อ, `E-COMP-*` ข้อเสนอจริงของรายอื่น (ไม่ระบุชื่อ), `E-HIST-*` ประวัติในระบบ, `E-KB-*` ความรู้ RAG (**ติดป้ายข้อมูลจำลอง** ไม่ทำให้ผู้ซื้อขยับ) — ไม่มีราคาขั้นต่ำในทะเบียน
- **ทุกรอบ** Agent วิเคราะห์ข้อเสนอ + ข้อโต้แย้ง → เลือกกลยุทธ์ (anchor, evidence_value, address_objection, conditional_concession, trade_off, contest_deduction, competitive_leverage, final_push) → อ้างหลักฐานที่ตรงข้อกังวล → เขียนข้อความ ความคิดของ AI ไม่แสดงบนหน้าเว็บ แสดงแค่กลยุทธ์ + เหตุผลสั้น + หลักฐาน
- **ผู้ซื้อจำลอง v2 (deterministic):** ให้น้ำหนักเหตุผลต่างกันรายละราย · ราคาอ้างอิงต้องสูงกว่าที่เขาให้จริงจึงมีผล · เหตุผลซ้ำน้ำหนักลดครึ่ง · ขอเกินงบมาก (>15%) ไม่ขยับ · ถูกโน้มน้าวแล้วงบยืดได้ · ทุกคำตอบที่ยังไม่ตกลงมีข้อโต้แย้ง · ไม่รับข้อเสนอสุดท้ายอัตโนมัติ ถอนตัวเมื่อเกินรอบ · ไม่อ่านข้อความอิสระ รับเฉพาะเหตุผลที่โค้ดตรวจหลักฐานแล้ว จึงหลอกด้วยคำพูดไม่ได้

### ประเมินคุณภาพการเจรจา (`npm run eval`)
25 สถานการณ์ (3 พืช × 4 บุคลิกผู้ซื้อ × มี/ไม่มีราคา NABC + ขั้นต่ำสูง) เทียบ "ไม่เจรจา" · "ตัวเลขอย่างเดียว" · "กลยุทธ์+หลักฐาน" (และ `--nova` สำหรับ Nova จริง จำกัดด้วย `--limit`) ผลล่าสุดอยู่ที่ [`docs/eval-report.md`](docs/eval-report.md):

| แบบ | ได้ดีล | ราคาสุทธิเพิ่มจาก "ไม่เจรจา" | เพิ่มจากข้อเสนอแรกของรายที่เลือก |
|---|---|---|---|
| รับข้อเสนอแรกที่ดีที่สุด | 8/25 | – | – |
| ตัวเลขอย่างเดียว | 17/25 | +0.61 บาท/กก. | +0.57 |
| กลยุทธ์ + หลักฐาน (AI สำรองแบบกฎ) | **25/25** | **+0.65 บาท/กก.** | **+1.46** |

*ผลทดสอบจากข้อมูลจำลองและผู้ซื้อจำลอง ไม่ใช่ผลในตลาดจริง · ยังไม่ได้รัน eval กับ Nova*
**ขีดจำกัด:** 14 ขั้น, LLM timeout 20 วิ, retry 1 ครั้ง, งบ token ต่อการเจรจา — LLM ล่มแล้วหยุดอย่างปลอดภัย ไม่มีดีลค้าง

```bash
cd backend
NABC_OFFLINE=1 npm run agent:demo                 # LLM จำลอง + ราคาตัวอย่าง (ไม่มีค่าใช้จ่าย)
NABC_OFFLINE=1 npm run agent:demo -- bitter_gourd # กรณีส่งเรื่องให้กลุ่ม
LLM_PROVIDER=bedrock BEDROCK_MODEL_ID=<จาก console> AWS_REGION=ap-southeast-1 npm run agent:demo   # Nova จริง
```
ผลทดสอบ (LLM จำลอง, ข้อมูลจำลอง + ราคา NABC 19 ต.ค.): ข้าว 41.5 ตัน → เลือกโรงสี C หลังต่อรองหักความชื้น 4%→1.5% และราคา 18.40→18.64 ราคาสุทธิเฉลี่ย 17.99 บาท/กก. สูงกว่าข้อเสนอแรกที่ดีที่สุด +0.69 บาท/กก. (≈28,635 บาททั้งกลุ่ม) — *เป็นผลทดสอบจากข้อมูลจำลอง ไม่ใช่ผลจริงในตลาด*

## Deploy บน AWS (CloudShell, `ap-southeast-1`)
```bash
git clone https://github.com/Natthanichan/mara-agrially && cd mara-agrially/backend
npm install
sam build
sam deploy --parameter-overrides BedrockModelId=<Nova model/inference profile ID>   # ยืนยัน changeset ด้วย y
```
ผลลัพธ์ `AppUrl` คือหน้าเว็บ (กด "เริ่มเจรจาด้วย AI" เพื่อรันดีลสด) · อัปเดตโค้ด: `git pull && sam build && sam deploy` · ลบทั้งหมด: `sam delete`

| Resource | ทำอะไร | ค่าใช้จ่าย |
|---|---|---|
| API Gateway HTTP API (throttle 10 req/s) | หน้าเว็บ + API + LINE webhook | จ่ายตามใช้ |
| Lambda `api` (15 วิ) / `worker` (180 วิ, ไม่ retry) | ตอบเร็ว / รัน Agent เบื้องหลัง | จ่ายตามใช้ |
| DynamoDB on-demand 1 ตาราง | ดีล, ledger, โควตา, snapshot ราคา NABC | จ่ายตามใช้ |
| Bedrock Amazon Nova (IAM อนุญาตเฉพาะ Nova) | Agent | ต่อ token · จำกัด `DailyNegotiationLimit` ครั้ง/วัน (ค่าเริ่มต้น 60) |
| CloudWatch Logs (เก็บ 7 วัน) | log | จ่ายตามใช้ |

ไม่มี EC2, NAT Gateway, load balancer หรือ OpenSearch · ใช้ LLM จำลองแทน Nova ได้: `--parameter-overrides LlmProvider=mock`

## LINE chatbot (`backend/src/line`)
ทีมเล่นบทเกษตรกร: พิมพ์ผลผลิตแบบอิสระ (เช่น “ข้าวหอมมะลิ 12 ตัน เกรด A ขั้นต่ำ 17 บาท/กก.”) → น้องมะระสรุปให้และมีปุ่มยืนยัน → เจรจาเบื้องหลัง → **ส่งข้อความหาเกษตรกรครั้งเดียว** ตอนมีผล พร้อมปุ่ม [อนุมัติ] [ไม่เอา] [ต่อรองใหม่]

| เรื่อง | รายละเอียด |
|---|---|
| Webhook | `POST /line/webhook` (และ `/api/line/webhook`) ตรวจ `X-Line-Signature` (HMAC-SHA256 กับ body ดิบ) ไม่ผ่าน = 401 |
| ค่าลับ | อ่านจาก SSM SecureString `/mara-agrially/line/channel-secret` และ `/mara-agrially/line/channel-access-token` (เปลี่ยนชื่อได้ด้วย parameter `LineChannelSecretParam` / `LineChannelAccessTokenParam`) ไม่เก็บในโค้ด |
| บทบาท | ผู้ใช้ LINE สวมบทเกษตรกร 1 คนในกลุ่มจำลอง (ข้าว=F01, มะระ=F06, มันสำปะหลัง=F09) ผลผลิตที่พิมพ์แทนที่รายการจำลองของคนนั้นเฉพาะดีลนี้ |
| สมาชิกคนอื่น | เป็นตัวจำลอง อนุมัติอัตโนมัติเมื่อผู้ใช้กดตอบ และ ledger ติดป้าย `simulated: true` |
| ไม่เอา | ผู้ใช้ถอนตัว คนที่เหลือไปต่อได้ถ้ายังผ่านราคาขั้นต่ำและปริมาณขั้นต่ำของผู้ซื้อ ไม่ผ่านก็ให้ต่อรองใหม่ |
| ต่อรองใหม่ | ยกเลิกดีลเดิม เริ่มดีลใหม่ด้วยผลผลิตเดิม ไม่เกิน 3 ครั้ง (นับโควตารายวันด้วย) |
| กันซ้ำ | `webhookEventId` ถูกจดไว้ (DynamoDB TTL 2 วัน) · ล้างร่างก่อนเริ่มดีลเพื่อกันกดยืนยันซ้ำ · ปุ่มของดีลใช้ได้เฉพาะเจ้าของ |
| ข้อความ | ใช้ reply (ไม่นับโควตา) เกือบทั้งหมด ใช้ push แค่ 1 ครั้งต่อดีลตอนเจรจาเสร็จ — แพ็กเกจฟรีของ LINE OA จำกัดจำนวนข้อความ push ต่อเดือน |
| ข้อจำกัด | อ่านข้อความด้วยกฎ regex (ไม่ใช้ AI) รองรับแชตส่วนตัวเท่านั้น (ไม่รองรับกลุ่ม) ปริมาณ 100–1,000,000 กก. ราคา 0.5–1,000 บาท/กก. |

**คุยกับน้องมะระ (แชต AI ด้วย Nova, `line/chat.ts`):** พิมพ์อิสระได้ทั้งเกษตรกรและผู้ซื้อ
- เกษตรกร: ถาม “ทำไมได้ราคานี้” “ผู้ซื้อรายอื่นให้เท่าไร” → ตอบจากดีลของเขาเอง (ข้อเสนอ ราคาสุทธิ แต่ละรอบที่ต่อรองและหลักฐานที่ใช้) · พิมพ์ผลผลิตแบบภาษาพูดได้ → AI สรุปเป็นการ์ดให้กดยืนยัน (ราคาขั้นต่ำต้องมาจากที่เกษตรกรพิมพ์เอง AI เดาแทนไม่ได้)
- ผู้ซื้อ: ถาม “ทำไมต้องจ่ายแพงกว่านี้” → อธิบายด้วยราคาตลาด NABC ปริมาณรวม เกรด รถรวม ช่วงส่งมอบ · บอกความต้องการแบบภาษาพูด → การ์ดคำขอซื้อให้ยืนยัน · ถามกลับระหว่างกรอกคำขอได้ แล้วบอทถามคำถามเดิมต่อ
- ความปลอดภัย: AI เห็นเฉพาะบริบทที่โค้ดเตรียม (ไม่มีชื่อ บัญชี หรือราคาขั้นต่ำของคนอื่น) · ตัวเลขในคำตอบต้องมีในบริบทหรือข้อความผู้ใช้ ไม่งั้นตอบใหม่ 1 ครั้งแล้วตอบแบบปลอดภัย · อนุมัติ/ไม่เอา/ต่อรองใหม่ ต้องกดปุ่มเท่านั้น · จำกัด `CHAT_DAILY_LIMIT` ข้อความ/วัน (ค่าเริ่มต้น 300) · ไม่มี Nova หรือ AI ล้ม → กลับไปตอบแบบกฎ
- พิมพ์ผลผลิตครบรูปแบบ (“ข้าวหอมมะลิ 12 ตัน ขั้นต่ำ 17 บาท/กก.”) ไปขั้นยืนยันทันทีโดยไม่เรียก AI

**การ์ดผลเจรจาใน LINE:** มีส่วน “น้องมะระต่อรองอย่างไร” (แต่ละรอบ: หลักฐานที่อ้าง ราคาที่ขอ ผู้ซื้อตอบ) + ปุ่ม “ดูการเจรจาทั้งหมด” เปิดหน้าเว็บของดีลนั้น

**เลือกบทบาท:** เพิ่มเพื่อน/พิมพ์ “เมนู” → ปุ่ม [ฉันเป็นเกษตรกร] [ฉันเป็นผู้ซื้อ] (บทบาทเก็บใน session) น้องมะระเป็นผู้หญิง ใช้ “หนู/ค่ะ” ทั้งข้อความบอทและ prompt ของ Agent

**กลุ่มเพื่อนเกษตรกร:** กด “ฉันเป็นเกษตรกร” → [มีรหัสกลุ่ม] [สร้างกลุ่มใหม่] [ให้น้องมะระหากลุ่มให้]
- รหัส `12345` (หรือ `1234`) = กลุ่มจำลอง ข้าวหอมมะลิ ร้อยเอ็ด 4 คน — ใช้ตอนเดโม
- สร้างกลุ่ม: ตั้งชื่อ → สุ่มรหัส 5 หลัก (DynamoDB `FGROUP#<code>`) เพื่อนใส่รหัสแล้วเป็นสมาชิกจริง **แต่การเจรจายังใช้กลุ่มจำลองในพื้นที่** (บอทบอกผู้ใช้ตรงๆ) — ต่อสมาชิกจริงเข้าการเจรจาเป็นขั้นต่อไป
- หากลุ่มให้: ใช้การจับกลุ่มเดิม (พืช + เกรด + จังหวัด) ตอนเริ่มเจรจาบอทบอกว่ารวมกับใคร กี่คน

**ฝั่งผู้ซื้อ (คนจริงใน LINE):** บอทถามทีละข้อ พืช (ปุ่มหรือพิมพ์) → ปริมาณ → สถานที่ส่งมอบ → ราคาที่เสนอ (บาท/กก.) → สรุปให้กดยืนยัน → บันทึกเป็น `BuyerRequest` (DynamoDB `BUYERREQ#<uid>` + ดัชนีตามพืช `BUYERREQ#OPEN#<crop>`) แล้วบอกภาพรวมผลผลิตที่มีในระบบ (ข้อมูลจำลอง ไม่มีราคาขั้นต่ำของเกษตรกร) · “คำขอของฉัน” ดูรายการ · “ยกเลิก” ล้างร่าง
**จับคู่และแจ้งเตือนผู้ซื้อ:** ยืนยันคำขอแล้วได้การ์ด (carousel) กลุ่มเกษตรกรที่ปลูกพืชนั้น: เกรด จังหวัด (บอกถ้าจังหวัดตรงกับที่ส่งมอบ — เทียบข้อความ ไม่ได้คำนวณระยะทาง) จำนวนสมาชิก ปริมาณรวม ช่วงส่งมอบ และปริมาณพอกับที่ต้องการไหม ไม่มีชื่อหรือราคาขั้นต่ำของเกษตรกร · เมื่อเกษตรกรใน LINE กดยืนยันเริ่มเจรจา ผู้ซื้อที่มีคำขอพืชนั้นเปิดอยู่ได้ push การ์ดกลุ่ม (คนละ 1 ข้อความ ไม่เกิน 5 คน เพราะนับโควตา push)
**ผู้ซื้อเจรจาราคากับน้องมะระ (`line/buyerNegotiation.ts`):** กด “สนใจ เจรจากับกลุ่มนี้” บนการ์ดกลุ่ม หรือพิมพ์ “สนใจ” → ใช้ราคาในคำขอซื้อเป็นข้อเสนอแรก → ต่อรองด้วยข้อความอิสระ (“ขอ 16.5 ได้ไหม”, “ทำไมแพงจัง”) หรือปุ่มลัด [ยอมรับราคา] [จบการเจรจา]
- **โค้ดตัดสินราคาทุกรอบ:** เปิดที่ max(เป้า×1.05, ราคากลาง NABC×1.04) ยอมลดเป็นขั้นตามที่ผู้ซื้อขยับ ไม่ต่ำกว่าราคาที่สมาชิกทุกคนยังผ่านขั้นต่ำ (คิดจากค่าขนส่งจริง) ครบ 6 รอบยื่นราคาสุดท้าย ผู้ซื้อเสนอสูงกว่าที่ขอ → ตกลงที่ราคาผู้ซื้อ
- **Nova เขียนข้อความโน้มน้าว** ตามการตัดสินนั้นด้วยหลักฐาน (NABC ปริมาณ รถรวม เกรด ช่วงส่งมอบ) ไม่เห็นราคาภายใน และราคาที่ตัดสินต้องอยู่ในข้อความเสมอ (ไม่มีก็เติมให้) ไม่มี Nova → ข้อความสำเร็จรูป
- ตกลงแล้ว: เกษตรกรในกลุ่ม (ตัวจำลอง) อนุมัติ · ทุกข้อเสนอ/การตัดสิน/การอนุมัติบันทึกใน ledger (`BNEG-*`) แบบ hash chain
**ยังไม่ได้ทำ (ขั้นต่อไป):** ผูกการเจรจาฝั่งผู้ซื้อกับดีลของเกษตรกรคนจริงใน LINE (ตอนนี้กลุ่มฝั่งผู้ซื้อเป็นข้อมูลจำลอง) และแสดงบน dashboard (ต้องให้ราคาที่ตกลงผ่านโค้ดและตรวจราคาขั้นต่ำเหมือนเดิม) ตอนนี้คำขอซื้อยังไม่ถูกจับคู่กับดีลของเกษตรกร ฝั่งเกษตรกรยังเจรจากับผู้ซื้อจำลอง

ตั้งค่า: LINE Developers Console → Messaging API → **Webhook URL** = ค่า `LineWebhookUrl` จาก output ของ `sam deploy` → กด **Verify** → เปิด **Use webhook** · LINE Official Account Manager → Response settings: ปิด Auto-response messages

## รันในเครื่อง
```bash
cd backend
npm install
npm test               # unit test ทั้งหมด
npm run dev            # ทั้งระบบในเครื่อง http://localhost:3000 (memory + LLM จำลอง)
npm run build:assets   # หลังแก้ knowledge/*.md หรือ web/index.template.html
npm run eval           # ประเมินการเจรจา 25 สถานการณ์ (ไม่มีค่าใช้จ่าย)
```
